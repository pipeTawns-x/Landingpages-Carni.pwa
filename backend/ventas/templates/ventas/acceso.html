{% load static vite %} {% comment %} Sign in and sign up: the real accessweb.html, painted by Django (ventas:acceso, /acceso/). Same idea as the original page, built mobile first: Don Carlos over one card, one form at a time on a narrow screen; on a wide one, two halves and Don Carlos' panel sliding between them. The sign-in logic is NOT in this file. Supabase Auth runs in the browser through static/tienda/acceso.js, which reads the ids, the data-* attributes and the field names below (#acceso, #acceso-aviso, #form-ingresar, #form-registro, [data-error], [data-accion], the `name` of every input). Change one of those and the script stops working; the look is free. The script flips `data-modo` on #acceso ("ingresar" or "registro") and the styles do the rest (css/pages/acceso-page.css). #acceso stays `hidden` until the script has its handlers: a submit before that would post a password. Don Carlos and the card are outside it, so the first paint does not wait for Supabase. CSP 'self': no inline style, no inline script, no CDN. Styles and scripts come from the Vite build ({% vite_asset %}), which writes Bootstrap before the site's own CSS.
